# Interlock — future scope (kept for further research)

Parked during hackathon planning (Oct 2026). Not part of the hackathon build.

1. **Self-repairing flows** — when an API, website or document changes and a flow starts failing, the system finds the first failing step, proposes a fix, replays past runs as regression tests and asks for one approval. Close to YC's Fall 2026 request for "self-maintaining APIs". A demo needs controllable "broken" sites.
2. **Multiplayer live runs** — teammates join a live run, see each other, redirect steps and hand off work. YC Fall 2026 lists "Multiplayer AI" as a request.
3. **Simulating outcomes before acting** — a world model predicts what each step will return and the likely outcome before the real run; predicted vs actual calibrates it. Research is active, but predictions are not yet reliable enough to demo safely.

Also researched and parked: reliability targets with measured verifier correlation (arXiv 2607.13918), information-flow control against prompt injection, and per-skill LoRA learning (Nemotron was not on Token Factory's fine-tuning list as of Oct 2026).
